Q Ecosystem

A personal, local-first lab that ties together the machines I have access to (a laptop, an older Intel Mac, my university's compute pool, a backup drive, and free cloud tiers) so I can build and run coding projects without paying for infrastructure.

Node map

Problem

I wanted to explore coding projects in simulation, data analysis, monitoring and AI tooling, but did not have the compute or budget for dedicated servers or cloud services. I did have access to scattered resources: my laptop, an older Mac, my school's engineering compute account, and the free tiers that cloud providers offer. The problem was turning those into one usable system rather than a pile of separate machines.

What I did

Designed Q: a collection of small, independent projects that share a few machines and one set of rules. I defined each machine's role, set the rules for what may run where, and had a node-map visualizer built so I can see what every node is doing at a glance.

My role: I design the architecture and rules, write the specifications, approve each build step, and verify results on separate machines. AI coding agents (Claude and Codex) write much of the code under those rules.

How

Machines

  • Main (M3 Max MacBook Pro, 36 GB): interactive development, architecture, and review. It is not an autonomous host.
  • Brain (older Intel Mac, 16 GiB): the primary execution machine, reached over a private Tailscale network. It runs deterministic Python and local Ollama models.
  • ECC (my university engineering computing account): used on demand only, through a guard script (the "Gate"). I run capped, low-priority research jobs (at most 4 cores, 16 GiB, 2 hours, 2 at a time) and the guard enforces those limits.
  • Backup: a 2 TB USB drive attached to Brain, tracked as a storage node.
  • Dispatch: a routing layer on Brain, planned to send tasks to free cloud nodes. Today it is a working skeleton with routing code and 14 tests, and one free cloud VM connected for a demo task. The other free-tier nodes (Google Cloud, Lightning AI, Kaggle, Colab) are registered but disabled.

Design decisions

  • Local-first, deterministic Python. Python does the deterministic work, local models on Brain handle any language reasoning, and Claude is used interactively for development and review, never as part of an autonomous loop. The stated reason: not to architect around continuous cloud-model or API usage.
  • Strict project isolation. Projects are independent by default, and integration is added deliberately only when it is useful.
  • Nothing runs in the background without approval. No service, schedule, or autonomous agent starts without explicit approval in that session. Scaffolding something is not permission to run it.
  • One guarded portal to the university account. The Gate checks every job, push, and status request and logs the decision. It blocks direct ssh, enforces the resource caps at lowest priority, refuses detached or scheduled jobs, rejects secrets in commands and pushes, and a watchdog kills over-limit jobs.

Projects in the ecosystem

Seventeen registered projects, each with its own scope and status (as of late October 2026).

  • Shoal (scaffold with code): physics-aware 3D maritime and swarm simulation.
  • Sentinel (working): intelligent local network monitoring and anomaly detection.
  • Concierge (working, manually invoked V1): the pixel-art personality and user-facing front end of the ecosystem.
  • Senate (scaffold with code): model-agnostic decision council with critique, deterministic voting, evaluation, and persistent learning.
  • Librarian (dormant): local intelligence and knowledge layer for my notes.
  • Tournament (dormant): benchmarking framework for models, agents, prompts, and algorithms.
  • Arena (dormant): isolated attacker-vs-defender cyber range.
  • Menagerie, Night Shift, Foundry, Forge, Graveyard, Cipher (dormant): observation of autonomous workers, approved unattended work, project scaffolding, an invention lab, a record of rejected ideas, and a cryptography lab.

Results

  • A working multi-machine system with one registry, one node map, and written rules, running on hardware and free resources I already had. Software and compute cost: zero.
  • Roughly 137,000 lines of Python and 18,000 lines of C# (including tests and fixtures) across the ecosystem, in 844 commits since September 13, 2026.
  • Seventeen registered projects: 1 live, 2 working, 4 scaffold with code, and 10 dormant. Examples include a swarm and maritime simulator (SHOAL), local network monitoring, and a multi-model decision council.
  • The guard script's audit log records each job and push it allowed or denied.
